# Coastal Links generation evidence

These images are **component fixture captures**, not authenticated gameplay screenshots. The fixture is a complete
Links course generated by backend course Generator 9 from seed coordinate `(103, 0, 0, 0, 0, 0, 0)`. The SVGs were
rendered by the production `Hole2d` / Premium Links component at a 1600 × 900 stage and exported to PNG with
Inkscape. No coastline was drawn into the fixtures by hand.

For this seed, **holes 7–13 are coastal (7/18, 39%)**; holes 1–6 and 14–18 are inland. Every selected hole has
one water polygon whose sea edge extends 1,200 yards to the same side, beyond the viewport, and whose shoreline
passes beyond both ends of the hole stage. It is not an enclosed pond. An existing small strategic water hazard
can still appear separately, as on hole 8. The second tested seed, 271, also produces seven coastal holes.

The coastline uses a shared course side and a contiguous stretch of holes. The course still stores holes in local
yard coordinates; it does not have a global parcel map joining individual shore vertices across holes. Water
inside the existing playable boundary uses the existing `WATER` surface. Sea farther beyond that boundary is
`OUT_OF_BOUNDS`, with the existing shot rules unchanged.

Regenerate the JSON fixture by running `CoastalLinksPreviewFixture` with the output path
`../frontend/src/lib/play/coastal-links-course-fixture.json` on the backend test classpath. With
`COASTAL_LINKS_CAPTURE_DIR` set to this folder, the coastal case in `course-family-render.test.tsx` writes the
production component SVGs; export those SVGs at 1600 × 900 to reproduce the PNGs. The development route
`/dev/coastal-links-preview?hole=7` provides an interactive view of the same 18-hole fixture.
